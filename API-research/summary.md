## Observations (written after reviewing the raw responses in calls.jsonl)

### Cost and money
- **Pricing basis:** every $ figure uses 1 credit = $0.30. The run itself used `CREDIT_USD=4560` from `.env`; the $ values were recalculated from the logged credits, and `.env` now says 0.3.
- **Credits are accounted exactly.** The `X-Credits-Used` header was present on every data call. In all three runs, the sum of logged per-call credits equals the balance difference to the cent: 27.05, 27.45 and 27.45 credits, 81.95 in total ($24.59). The balance went from 15200.0 to 15118.05.
- **Person search costs more than the docs say.** With no `fields`, the bill was 1.65 credits for 5 results, or 0.33 per result. The docs quote 0.23 per result.
- **Company enrich bills every returned match, not every input.** 5 domains cost 12 credits, because `beardsell.co.in` returned 2 records at confidence 1.0 and both were billed. Budget about 2.4 credits per input, not 2.
- **Company identify by name bills even when it finds nothing.** Default (fuzzy) name matching returned 25 matches for a made-up company and charged 0.2 credits (see identity matching below).
- **Company search premiums apply.** `basic_info`, `headcount`, `funding` and `locations` plus the taxonomy filter cost 0.53 credits per result: 5.3 for 10 results. With only `basic_info.name` it was 0.13 per result.
- **Latency is unpredictable.** The same 5-domain enrich took 5.5 s, 23.3 s and 12.4 s across the three runs. In the final run, the single-URL web fetch took 157 s and one job search took 53.8 s, against 1–2 s for both elsewhere. Set long client timeouts; the script uses 120 s, and the 157 s fetch still came back.

### Coverage gaps, especially small Indian firms
- **The small-firm test is inconclusive.** For the tiny transporter in `.env`, `unik plywood`, identify returned only unrelated fuzzy matches (UNIK advertising, UniK B.V., Unik.ch, each at 0.6). Nothing showed the firm exists in Crustdata. Whether it should have been found is unclear, because its existence wasn't independently verified.
- **Search does reach small companies.** It returned companies with 6 to 25 employees (DIKSAT TRANSWORLD with hc=6, Coastal Roadways with hc=20, Concor with hc=25). That Concor (Container Corporation of India) shows a headcount of 25 is surprising, since it is a large public-sector company.
- **Enrich on small firms is sparse.**
  - ABC India: `hiring` entirely null, `funding` 8/14 fields null.
  - The duplicate BEARDSELL LIMITED record (id 15542175): `competitors`, `hiring` and `people` empty, `funding` 11/12 fields null.
- **Person search found nobody at Blue Dart.** It returned 0 supply-chain or logistics heads, filtering by `current.company_website_domain = bluedart.com` and also by `company_name (.) "Blue Dart"`. Yet enrich shows Blue Dart with 10,946 headcount and 66 decision makers. Delhivery returned 28 matches. Whether this is a coverage gap or how Blue Dart titles are worded is unclear.
- **Watchers aren't listed for this account.** `/account/endpoints` doesn't list any `/watch/*` endpoints, although `GET /watch/company/search` returned `200 []`. Whether watchers are enabled on this plan is unclear.

### Null-heavy fields
- **`funding.total_investment_usd`** is `0.0` for most non-VC Indian companies (Allcargo, Blue Dart, ABC India) and `None` for others. A `0.0` can't be told apart from "unknown".
- **`funding.last_fundraise_date`, `last_round_type` and `last_round_amount_usd`** were null for 4 of 5 companies. Only Delhivery had them.
- **`hiring.recent_openings`** was empty for all 5 companies. Many `hiring.by_function_qoq_pct.*` and `by_function_6m_pct.*` values are null, and `hiring.openings_count` is null for small firms.
- **`competitors.paid_seo` and `organic_seo`** were empty for 3 of 5 companies.
- **`updated_at` and `indexed_at` (top level)** didn't appear at all for any company, though the docs list them on `company_data`.
- **Person enrich:** `updated_at` and `basic_profile.last_updated` were null for the enriched profile. Other null fields were `languages`, `location.full_location`, `profile_picture_permalink` and the twitter and dev-platform handles.

### Identity matching
- **Messy inputs resolved, but only barely.** All three Delhivery inputs (name, domain, LinkedIn URL) resolved to `crustdata_company_id` 5798. But for "DELHIVERY LTD", the right answer scored 0.6, tied with "Delhivery courier" (1236802) and "Delhivery courier service" (1236803), and came back alongside 25 matches. Match by domain or LinkedIn URL; treat name matches as candidates only.
- **Name identify never returns "not found" by default.** A made-up name returned 25 unrelated "Pvt Ltd" companies (Shahi Exports, Vestige, Honda Motorcycle…), all at 0.6, and billed 0.2 credits. With `exact_match: true` the same name returned 0 matches at 0 credits. The expectation in test 8 holds only with `exact_match: true`, so that is what test 8 checks.
- **Parent and brand links are missing.** Honasa Consumer (1132667) and Mamaearth (5844) came back as separate entities, as did Blue Dart (736) and Blue Dart Aviation (1994185). No parent, subsidiary or brand field came back. Mamaearth also has several junk duplicates: two lowercase "mamaearth" records with no domain, both at confidence 1.0, plus "Mamaearth Dummy", which shares the domain mamaearth.in.
- **Shared domains.** Identifying `mamaearth.in` or `bluedart.com` by domain returned exactly 1 match whether `exact_match` was true or false, so the flag changed nothing here. "Mamaearth Dummy", which also has `mamaearth.in`, was not returned. Domain identify seems to pick one canonical record, but enrich by domain does not: `beardsell.co.in` returned two records at confidence 1.0. The first one (15542175) is a thin duplicate, not the ID that search returned (583). Pick enrich results by `crustdata_company_id`, never by `matches[0]`.
- **Competitor results are noisy.** `competitors.websites = delhivery.com` (310 results) includes clear logistics peers (Blue Dart, Mahindra Logistics, Ecom Express), but also Duropack (packaging) and "Desired Destination" (balurghat.co.in).

### Web search quality
- **The fraud query isn't company-specific.** "Delhivery fraud news" (`sources: ["news"]`, `location: "IN"`) returned 10 results and **none mentioned Delhivery**. They are generic Hindi-language delivery-scam stories. For a compliance check, the query needs to be stricter, such as a quoted name, and the results need checking for the company name.
- **Most result URLs are redirects.** 15 of 19 were `https://www.google.com/goto?url=…` links. Fetching one in the first run returned a Google page titled "Google" with no article. Only direct URLs can be fetched usefully.

### Rate limits
- **Search, enrich and identify allow 5 requests per minute each** on this account (`effective_rate_limit_rpm`; web search and fetch allow 10). The first run hit one `429` on `/company/identify` after 5 quick calls: `{"error": {"type": "rate_limit_error", "message": "Rate limit exceeded for this endpoint. Please write to gtm@crustdata.co.", "metadata": []}}`. Later runs pace calls using `/account/endpoints` and got no 429s. A 20-account job therefore runs at 12 s or more per call on these endpoints, unless the batch endpoints are used, and those are `disabled` on this account.

### Other surprises
- **Headcounts disagree.** Beardsell's headcount is 96 in search (id 583) but 47 in the duplicate record that enrich returns first.
- **Hiring counts disagree with job search.** Delhivery's `hiring.openings_count` is 14, but job search found 37 Delhivery jobs added in the last 30 days. For Blue Dart the two agree (90 and 90).
- **The ID sort worked.** Sorting on `crustdata_company_id` was accepted, and both pages came back in ID order with no duplicates.
